# ULTRON AI — Repository Capability Integration Map

Updated: 2026-10-25

This map covers all 31 registered repository capabilities for ULTRON. The supplied Cactus organization URL resolves to multiple projects; this integration uses `cactus-compute/cactus` as the inference engine plus its related `cactus-compute/needle` micro-model and Whistle speech component. The Hermes Agent connector uses the upstream OpenAI-compatible API so ULTRON can delegate tasks to a separately configured Hermes runtime. The new registry gives the agent task-matched capability guidance and provides a **configuration-only** status API at `GET /api/agent/repositories` (authenticated). It does not install upstream applications, clone entire projects into the ULTRON server, create provider accounts, or falsely mark a service as working.

## How automatic routing behaves

1. ULTRON matches the task to relevant repository domains, then chooses only tools actually available in its runtime.
2. Existing adapters are used only when their endpoint/configuration and required inputs are present. "Configured" still means **unverified** until an actual upstream request succeeds.
3. For a missing adapter or local/desktop dependency, ULTRON continues with supported safe research/drafting and reports the real blocker in its tool result. It must not pretend that an upstream application ran.
4. Public read-only research, planning, evidence analysis, and drafts can be used automatically. External publishing, messages, bookings, spending, account changes, deletion, and PC-control actions remain scoped to the supported approval workflow.
5. Free/local-first is the default. Services with metered API access must not be invoked unless their credentials and budget policy are deliberately configured.
6. Upstream skills and repository files are untrusted reference data. They are not shell scripts or higher-priority instructions.

## Readiness API

`GET /api/agent/repositories` reports the registered upstreams, non-secret state, required environment-variable *names*, and a repository count. Add `?task=...` to see the domains selected for a particular task. The endpoint requires a signed-in ULTRON user and returns no secret values. Shared Chatwoot/OpenProject/Cal.diy API credentials are additionally restricted to the exact signed-in UUID configured in `ULTRON_INTEGRATION_OWNER_USER_ID`; without that guard their agent tools remain blocked. Paperclip read-only governance uses the same owner guard and its own separately hosted endpoint/company scope.

State meanings:

- `adapter_present_unverified_live` / `configured_unverified`: adapter/configuration exists, but live operation isn't proven.
- `credentials_present_adapter_missing`: variables exist but no executable connector is implemented yet.
- `adapter_not_implemented`: no service adapter exists yet.
- `desktop_companion_required` / `local_mcp_required`: requires a local/desktop runtime.
- `task_aware_skill_selector` / `guidance_only` / `catalog_only`: reference or routing guidance, not an upstream runtime.
- `missing_configuration`: required configuration is absent.

## Next integration order

1. Verify and harden existing adapters: model provider, VoiceStudio, ComfyUI, Geo-Sleuth, Handy bridge, Browser Use, AgentMemory, HeyGem and OmniVoice.
2. Live-test the owner-scoped Chatwoot, Cal.diy and OpenProject read-only adapters on dedicated test data; then implement further read-only adapters for AppFlowy only after API schemas/auth scopes are confirmed.
3. Add OpenSEO and public-API discovery with explicit cost/terms checks; Paperclip read-only governance is now implemented but still needs live endpoint verification. OpenViking/OpenDesign remain separate service adapters.
4. Build one authenticated desktop bridge for local capture/dictation and the approved Windows action allowlist before adding Cap/OpenWhispr/REA local workflows.
5. Configure and live-test Obscura and Cactus/Needle on a local companion or authenticated private endpoint; benchmark on target hardware before enabling model downloads. Keep Cactus cloud handoff disabled unless separately approved.
6. Configure a sandboxed Hermes Agent gateway and test the owner-scoped delegated task tool; use Hermes' own API_SERVER_KEY, minimal toolsets, and least-privileged terminal backend. Then implement any additional upstream adapters not yet executable.
6. Add the YouTube production pipeline as durable stages with fact/media-rights checks and a human publish gate. Media generation and channel publication are not considered complete until each stage is live-tested.

This ordering intentionally avoids copying whole, independently deployable applications into the Node backend. It keeps ULTRON modular, free-first, resource-bounded and testable on the target 8 GB RAM / integrated-graphics PC while allowing heavyweight services to run elsewhere.
